# Maintaining the public directory

Applicability: authorized maintainers of this repository's public agent documentation. Initial review 2026-09-29; targeted identity reconciliation 2026-10-19.

## Ownership and update path

This folder is the public distribution layer for established identity and operating context. User's newest explicit assignment controls User-defined facts. Maintained Notion owners govern operating identity/behavior; Drive owns product/design/canon and visual appearance; Linear tracks execution; provider/runtime evidence controls actual capabilities and implementation. Public and Drive bridges should carry the useful current state without becoming competing authorities.

When a name, role, behavior, source route, or access fact changes, reconcile the owning record and the dependent public profile in the same authorized maintenance task. If the owner cannot be updated, record that concrete propagation gap in the active internal issue; do not silently claim global synchronization. Preserve original historical authorship when it remains useful.

## Adding or changing a profile

1. Read the current source and newest applicable User assignment. Establish whether this is a standing persona, configured worker, specialist profile, scoped role, execution surface, or generic template.
2. Reuse the existing stable path for a rename. Record current name and only useful aliases; do not resurrect a superseded current nickname as a second active identity.
3. Keep identity, badge, provider/model/host, role, status, access, voice, appearance, and evidence boundary explicit. Leave unassigned fields unassigned.
4. Begin with an applicability gate. A reader adopts the identity only through an actual assignment; others use it for reference/routing.
5. Make the profile usable from one file: current scope, voice, work, boundaries, calibration, essential shared context, source basis, and raw links for deeper guidance.
6. Update `manifest.json`, the directory table, review dates, and affected guides. The manifest is the machine-readable catalog, not a second prose behavior owner.
7. Inspect the diff, check local targets and raw URL construction, run the repository's required validation, publish, and read the anonymous raw result back. Verify the changed content, not merely HTTP status.
8. Update the internal discovery bridge and execution receipt. A successful public readback is not proof that all recipient providers installed or read the update.

Do not assign new badges, surname lineages, or executive offices in an editorial cleanup. The core eight Bot set and Haggle Bot's separate status remain explicit until User changes them. Model releases do not automatically change personality or office.

## Public-safe scope

Include the context a new agent needs to recognize colleagues and perform authorized TCS work: personality, role, relationships within the agreed immersive model, source ownership, operating boundaries, public terminology, and routing.

Keep credentials, private document IDs/URLs, login addresses, direct-message exports, incidental personal history, and private operational secrets outside this folder. Source titles and public vendor URLs can explain provenance without exposing the internal workspace. Any later private-to-public transfer still needs authorization appropriate to its scope.

## Versions and continuity

Use `main` raw URLs for maintained current guidance. Use commit-pinned raw URLs for reproducible evaluation or a historical handoff. Record the version when exact reproducibility matters. Do not call a living profile FINAL. Do not rewrite a current file into a long archive of obsolete corrections; retain only history that serves recognition, authorship, or a live decision.

Native configuration rollout is separate. Loading a document, updating a Drive bridge, modifying a provider profile, and confirming native application are different actions. Track each honestly. If a provider has no URL retrieval, supply the same file as an attachment or paste rather than inventing another policy corpus.
